ENTRY G01-004 — 2026-08-14 — KILLER-FEATURE ROUTING / PRODUCT POSITIONING
================================================================================

Graphium positioning frozen from the target-user findings:
  FAST + SIMPLE + SAFE + NATIVE GTK

Killer features / differentiators, in priority order:

0. PERFORMANCE / PERCEIVED IMMEDIACY
   Speed is an admission condition, not a decorative feature. If Graphium feels
   materially slower than the lightweight-editor class, the rest of the feature
   advantage will not persuade the core Leafpad/L3afpad audience.

1. TRANSPARENT STRONG FILE SAFETY
   Preserve a small UI while adding mature behavior behind it:
     strong accepted file identity;
     changed/replaced/deleted-file awareness;
     guarded and atomic writes;
     savepoint-aware Saved/Modified state;
     alias/topology/race protection;
     no silent overwrite after external mutation.
   Safety should be mostly invisible until it prevents data loss.

2. ENCODING / BOM / EOL CLARITY
   Status/Properties should make the active representation understandable without
   forcing technical details into dialogs. Preserve representation safely and allow
   bounded explicit conversion later if authorized.

3. PERSISTENT ESSENTIAL PREFERENCES
   Graphium must remember user choices such as wrap, font, line numbers, status bar,
   tab width/spaces-tabs, appearance and useful window geometry. Minimalism does not
   mean forcing repetitive setup at every launch.

4. MATURE PRINT WORKFLOW
   Print / Print Preview / Page Setup belong to the serious desktop-editor experience.
   They must not enlarge the startup critical path.

5. COMPACT HIGH-VALUE STATUS
   Line/column, word/character count, encoding, EOL and Saved/Modified state provide
   concrete utility with very little UI surface.

6. MODERN APPEARANCE WITHOUT THEME BLOAT
   System / Light / Dark is retained. No theme marketplace/editor or cosmetic platform.

7. SAVE A COPY / SAVE VERSION COPY
   Distinctive safety/workflow value inherited from Calamus without rebinding the active
   document or polluting the simple one-file mental model.

Explicit competitive REJECT decisions remain:
  syntax highlighting in v1;
  tabs / multi-document window;
  IDE subsystems;
  project/workspace/file-browser systems;
  plugin platform.

Reason:
  Graphium should not become a smaller Geany/Kate or chase the Mousepad code-editor
  segment. Its value is mature plain-text editing with unusually strong safety.
